# Theming

Crate: `libero`
Import: `use libero::{LiberoProvider, theme::{HexColor, Size, Sizes, Theme}};`
Index: [index.md](index.md) - every other component's markdown page
Description: How a Libero theme is defined: one plain struct of colors, scales and per-component defaults, emitted once as CSS custom properties.

`LiberoProvider`'s `themes` takes a `&'static Theme` and defaults to
`Theme::DEFAULT`. A theme is one plain struct with a color per role, the spacing
and radius scales, and a defaults struct per component. Customizing it is struct
update syntax over the default, in a `static`.

The provider renders it once as custom properties on `:root`, so the strings in
`sx` need no lookup in Rust. `"primary.3"` compiles to `var(--lsx-primary-3)`.

## A custom theme

Only the fields you name change. The rest come from `Theme::DEFAULT`, a
`const`, so it can seed a `static`. The provider takes a `'static` reference, so
the theme is never cloned per component.

```rust,ignore
static THEME: Theme = Theme {
    primary: HexColor::new(0x7C3AED),
    spacing: Sizes::new(4, 8, 12, 16, 20, 24),
    ..Theme::DEFAULT
};

fn App() -> Element {
    rsx! {
        LiberoProvider {
            themes: &THEME,
            Router::<Route> {}
        }
    }
}
```

## Colors

Each palette role is a single `HexColor`. Its nine shades are generated by
mixing towards white and black, so a new brand color is one hex value, not a
ramp you design. A bare name is shade 6, the hex itself. Every shade has a
`-contrast` twin, black or white, whichever reads on it, so a component can pick
legible text for any background.

A color resolves through the role it is used in, so it stays legible without
every call site checking. `color()` asks for the text role and `background()`
for the fill role, each its own ramp. The text ramp starts at the palette color
moved just far enough from the page to reach 4.5:1. The fill ramp starts where
its black or white foreground reaches it. So `primary` is `#228BE6` as a border,
a ring or a decoration, and `#1D78C8` as a label or under white text. The muted
ramp is taken literally, so quiet text asks for it by name, with `text-dimmed`.

The roles are `primary`, `secondary`, `success`, `error`, `warning`, `info`,
`neutral` and `muted`, plus the plain `ink` and `surface`. `neutral` is the dark
text role a control uses when it should not compete with the page's accent.
`muted` is measured as distance from the page (borders, dividers, quiet text),
so it is greyish on a light theme and the reverse on a dark one. A shade in `sx`
is `role.shade`:

```rust
use dioxus::prelude::*;
use libero::{components::Box, sx::sx};

#[component]
fn Demo() -> Element {
    rsx! {
        Box {
            sx: sx().background("primary.3").color("primary-contrast.3").padding("md"),
            "Legible on shade 3, whatever the brand color is"
        }
    }
}
```

## Scales

`spacing` and `radius` are a `Sizes<u8>`, one pixel value per step from `xs` to
`xxl`. Size words in `sx` resolve through them, and every component's `size`,
`gap` and `radius` prop steps along them. `elevation` has the same shape in
`&'static str`: one `box-shadow` per step, from `xs` for a resting surface to
`xxl` for a modal. A `Dialog`'s shadow and an `elevated` `Button`'s come from
it. Components with a size of their own ([`Dialog`](dialog.md),
[`Drawer`](drawer.md), [`Sidebar`](sidebar.md)) carry their own `Sizes` in their
defaults struct.

## Component defaults

Every component's unset props come from its own struct on the theme, so "our
buttons are always pill-shaped" is a theme change, not a prop repeated at every
call site. Nested struct update works the same way, seeded from the component's
own `DEFAULT`.

```rust,ignore
static THEME: Theme = Theme {
    // Every component's own defaults are a struct of their own.
    mark: MarkDefaults { color: Color::Info },
    button: ButtonDefaults {
        radius: Size::Xl,
        ..ButtonDefaults::DEFAULT
    },
    ..Theme::DEFAULT
};
```

## Light and dark

One theme is shorthand for a `ThemeSet` of only that theme. A set names every
theme an app ships, and which is its light and which its dark. An app that names
none gets `ThemeSet::DEFAULT`, which pairs `Theme::DEFAULT` with `Theme::DARK`,
so `prefers-color-scheme` works with no JavaScript.

```rust,ignore
LiberoProvider {
    themes: ThemeSet::new().light(&LIGHT).dark(&DARK).named("sepia", &SEPIA),
    Router::<Route> {}
}
```

Both halves of the pair are in the sheet from the first paint, so switching
between them is one attribute on the document root, without a re-render. That
holds under SSR too:

```css
:root { /* the light theme */ }
@media (prefers-color-scheme: dark) {
  :root:not([data-lsx-theme]) { /* the dark theme, system case */ }
}
:root[data-lsx-theme="light"] { }
:root[data-lsx-theme="dark"]  { }
```

A theme added with `named` is not in that sheet. Selecting one rebuilds it, so
the sheet does not grow with every theme an app owns.

### The ones we ship

`ThemeSet::CATALOGUE` holds every set the library ships: `Libero`, plus `Ayu`,
`Ayu Mirage`, `Catppuccin`, `Dracula`, `Ef Night`, `Everforest`, `Flexoki`,
`GitHub`, `Gruvbox`, `Gruvbox Classic`, `Gruvbox Soft`, `Kanagawa`,
`Kanagawa Dragon`, `kettek16`, `Nord`, `One`, `Osmium`, `Rosé Pine` and
`Vague`. Each is a light and dark pair. Where a palette is dark-only upstream,
its light half is the palette's own light variant. Only `Vague`, `Osmium` and
`kettek16` have none and get one derived from their dark half. The picker in
this site's header is built from it:

```rust,ignore
let themes = use_theme_set();

for set in ThemeSet::CATALOGUE {
    rsx! {
        Button { onclick: move |_| themes.set((*set).clone()), "{set.name()}" }
    }
}
```

`use_theme_set()` gives `get()`, `name()` and `set()`. Swapping a set rebuilds
the stylesheet, because the pair in the sheet is that set's pair. The
color-scheme setting is kept, so a reader who pinned dark stays in dark.

A ported palette is ten hex values. Upstream names colors by their job, so
`bg`, `text`, `text-muted`, `accent`, `highlight`, `accent-soft`, `progress`,
`danger` and `raised` land on `surface`, `ink`/`neutral`, `muted`, `primary`,
`secondary`, `info`, `success`, `error` and `paper.background`. Everything else
derives. `warning` is the exception: no ported theme takes the palette's own, so
every one keeps Libero's amber, and on a cream page that is the one role below
4.5:1.

### The switch

[`ColorSchemeButton`](color_scheme_button.md) is the ready-made switch. It steps
from following the platform, to the other scheme, to the platform's own scheme
pinned, and back, so a reader can always return to the platform's choice. With
`themes` it adds a theme-set picker beside it. Anything else is built on
`use_color_scheme()`, out of an `ActionIcon`, a `Switch` or a
`SegmentedControl`:

```rust,ignore
let scheme = use_color_scheme();

rsx! {
    ActionIcon {
        aria_label: match scheme.resolved() {
            ColorScheme::Dark => "Switch to the light theme",
            ColorScheme::Light => "Switch to the dark theme",
        },
        onclick: move |_| scheme.toggle(),
        if scheme.resolved() == ColorScheme::Dark { SunIcon {} } else { MoonIcon {} }
    }
}
```

`setting()` is what the app asked for (`System`, `Light` or `Dark`) and
`resolved()` is the scheme on screen. `set(ColorSchemeSetting::System)` hands
the choice back to the platform. `set_theme("sepia")` selects a theme beyond the
pair. Every read is reactive, so a control showing the scheme re-renders when
the platform changes its scheme too.

On the web the choice is kept in `localStorage` under `lsx-color-scheme`. Off
the web it lives for the session, and the app persists it if it wants to.

### No flash on load

A stored choice has to reach the document root before the first paint, and the
wasm bundle has not run by then. So an app that persists one pastes
`libero::theme::COLOR_SCHEME_RESTORE_SCRIPT` into the head of its own
`index.html`. `LiberoProvider` cannot do it, because a `<script>` a renderer
inserts into the DOM never runs:

```html
<script>try{var s=localStorage.getItem('lsx-color-scheme');
if(s==='light'||s==='dark')document.documentElement.setAttribute('data-lsx-theme',s)}catch(e){}</script>
```

It is inline, so a strict CSP needs its hash:
`sha256-i2dSUtjYkvH3Km+1WnMbJX1ZfgYnbdyuKeoc3clqFQ0=`. Without the script
everything still works. The page paints the system scheme for one frame before
the app restores the stored one.

### Authoring a dark theme

A dark theme is a theme whose `surface` is dark. The palette bases can stay,
because the text and fill roles are derived against `surface`, and the `muted`
ramp is mixed between `ink` and `surface`, so swapping those two turns it round.
Only what the theme states as a literal CSS color has to change, which is why
`Theme::DARK` spells out five `*Defaults`.

The words components say and how dates are written are not in the theme. See

## Reading the theme

`use_theme()` returns the active `&'static Theme`. Components use it for values
they cannot express as CSS, such as `z_index` or a default that changes which
element renders. This docs site uses it so a demo control opens on the theme's
real default.

```rust,ignore
let theme = use_theme();

Control::color("color", [..]).default(theme.mark.color.as_str())
```

## What it emits

One stylesheet, once, at the provider: a custom property per theme value, plus a
small reset. Nothing else in Libero reads the theme at render time to produce
CSS, so a component's styles can be one cached class whatever the theme says.

```css
:root {
  --lsx-primary-6: #7c3aed;
  --lsx-primary-contrast-6: #ffffff;
  --lsx-spacing-md: 12px;
  --lsx-radius-md: 8px;
}
```

## Theme fields

`Theme` is not `Copy`: at about 2 KB, a stray by-value use would be a silent
memcpy. `Theme::DEFAULT` is a `const`, and `use_theme()` hands out
`&'static Theme`.

| Field | Type | Description |
|---|---|---|
| `spacing` | `Sizes<u8>` | Pixels per spacing step; what `gap`/`padding` size words resolve through. |
| `radius` | `Sizes<u8>` | Pixels per radius step. |
| `elevation` | `Sizes<&'static str>` | One `box-shadow` per elevation step. |
| `primary`, `secondary`, `success`, `error`, `warning`, `info`, `neutral`, `muted` | `HexColor` | One hex per palette role; the 1-9 shade ramp and its `-contrast` twin are generated. |
| `ink`, `surface` | `HexColor` | What text is set in, and the page it is set on. Every color role is derived against `surface`. |
| `font_smoothing` | `bool` | Whether the reset asks for antialiased text. |
| one field per component | `*Defaults` | For example `button: ButtonDefaults`, `dialog: DialogDefaults`, `mark: MarkDefaults`. Each component's markdown page documents its own struct. |

## CSS variables

Everything the theme emits lives under the `--lsx-` prefix on `:root`.

| Variable | Description |
|---|---|
| `--lsx-<role>-<1..9>` | A shade of a palette role; shade 6 is the brand color itself. |
| `--lsx-<role>-text-<1..9>` | The same ramp re-based on the first shade that reads on the page; what `color()` resolves a palette color through. |
| `--lsx-<role>-fill-<1..9>` | The same ramp re-based on the first shade that carries a black or white foreground; what `background()` resolves through. |
| `--lsx-<role>-contrast-<1..9>` | Black or white, whichever reads on that step of the fill ramp. |
| `--lsx-text-dimmed` | Secondary text: a placeholder, a hint, a unit. Written `"text-dimmed"` in an `sx`. |
| `--lsx-spacing-<size>` | A step of the spacing scale. |
| `--lsx-radius-<size>` | A step of the radius scale. |
| `--lsx-shadow-<size>` | A step of the elevation scale. |
| `--lsx-<component>-*` | A component's own defaults; see that component's page. |
